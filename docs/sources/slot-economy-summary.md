# Slot机台经济系统 —— 完整逆向梳理总结

本文档是这次对话里逐步核对出的完整数值逻辑总结，配套的Skill（供另一个Agent拉线上数据验证用）
已单独打包，见文末。

## 一、系统全貌

```
机台基础经济(Slot Base Economy)          积分事件卡点系统(Points Race Checkpoint)
────────────────────────────          ─────────────────────────────────
单次spin → 图标组合 → 宏观结果            体力/进度 → 节点a/节点b → 三段体验区
   ↓ 100%基准金币RTP                        ↓
运营活动开启时按级联概率替换图标           过渡关动态压制系数 / 卡点关硬阀门
   ↓                                        ↓
积分/体力/宝箱等活动奖励                   付费水池 → 独立替换线 → 补差价过关
```

## 二、机台基础经济 —— 核心结论

1. **图标字典**：C=金币 D=主题 S=盾 A=炮 R=偷 E=体力 L=777，另有P/K/H/B四种活动限定图标
   （积分/组队蛋糕/挖宝/Bet宝箱）
2. **单次spin结果**（`SlotBase`）：12类互斥宏观结果，权重合计100000，与`SlotWeight`的25行具体
   图标组合完全对应（已用真实配置表核对，C组/D组/三连/杂色求和分毫不差）
3. **金币RTP的准确含义**：消耗1体力→机台基准产出X金币（100%基准线，不叫RTP）；活动的"金币RTP"
   是在这条基准线之上的**额外**返还比例，多活动叠加时累加
4. **替换机制**：运营活动开启时，原生结果按**级联互斥分支**（不是独立叠加）被替换成活动图标；
   替换概率受"金币水池调控"的Amp/DecayCoef动态放大或衰减
5. **待补漏洞**：双积分/三积分图标目前不受水池调控影响（Amp/DecayCoef=0/0），产品文档已提出
   要拆成四行独立配置，但配置表还没更新上

## 三、积分事件卡点系统 —— 核心结论

1. **三段体验区**：奖励关(纯自然概率) / 过渡关(动态压制系数) / 卡点关(硬阀门+消耗上限解除)
2. **节点a/b用"第几个大节点"计数**，不是StageID——这是本次核对中最容易搞错的一点
3. **节点b是动态的**：会根据玩家实际进度/预期进度的比值，在允许区间内持续重新定位（追赶/减速），
   本质是个带上下限约束的P控制器
4. **过渡关压制系数 = 进度系数 × bet系数 ÷ 过渡关编号系数**，三个独立可调的分段函数
5. **付费走独立通道**：钱进水池(有7天有效期，历史均值按0.92衰减加权)，水池有余额时用独立的
   `PayReplaceGroupID`，且能在卡点关直接"补差价"抵消消耗上限

## 四、仍需产品/程序确认的关键缺口

| # | 缺口 | 影响 |
|---|---|---|
| 1 | 所有"按Indicator分档"表的查表规则(推断为取≤指标的最大档) | **影响全部节点/系数计算结果**，务必优先验证 |
| 2 | 双/三积分图标Amp/DecayCoef=0/0是否是已知待补漏洞 | 影响水池调控的实际生效范围 |
| 3 | "挖宝活动"与规划表里"爬塔活动"是否为同一活动 | 影响活动RTP账本对不对得上 |
| 4 | 付费水池"付费金额对应系数"缺配置表 | 付费水池金额可能算少了 |
| 5 | CheckpointK=100%是否为最终设计值 | 影响卡点关是否保留随机性 |
