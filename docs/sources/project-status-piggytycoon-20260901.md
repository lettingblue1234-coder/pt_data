## 一、环境事实（已验证，不用再试）

| # | 事实 |
|---|---|
| 1 | 引擎是 **Trino/Presto**，不是 ClickHouse。反引号报错，用双引号包字段名 |
| 2 | 编辑器**不支持行尾注释**，注释必须独占一行，实践上全部不写 |
| 3 | 所有埋点在一张宽表 **`ta.v_event_261`**，`"$part_event"` 区分事件，`"$part_date"` 按天分区 |
| 4 | 用户属性表 **`ta.v_user_261`**，一账号一行，JOIN 安全 |
| 5 | 部分工具会**吃掉首字母**，粘贴后确认第一个词是 `WITH` 不是 `ITH` |
| 6 | **`$part_date` 与 `date("#event_time")` 一致**（已诊断验证，4 行全部相等，跟随会话时区） |

### 字段坑（全部实测过）

| 要什么 | 写什么 | 备注 |
|---|---|---|
| 国家 | 事件表用 **`"#country"`**；用户表用 `country` | 事件表写 `country` 会报 cannot be resolved |
| 操作系统 | **`os`**（无 `#` 前缀） | `#os` 报错。取值只有 `IPhonePlayer` / `Android` |
| 平台 | `platform` **不可用** | 全是 `piggytycoon_global`，是发行包标识 |
| 等级 | `t_logout` 的 `curr_lvl` | 只有这个事件有值；量级看着像 2000-4000，**含义存疑** |
| 地块 | `polt_id` | 拼写就是错的，照抄 |
| 商品 | `product_id`（**未验证**）或 `trade_id` | 报错就互换 |
| 广告系列 | `ad_series`（**未验证**） | 截图里有 `#vp@ad_series` 虚拟属性和 `ad_channel` 用户属性 |

### 归一化写法（固定用这个）

```sql
CASE
    WHEN os_raw = 'Android'      THEN '安卓'
    WHEN os_raw = 'IPhonePlayer' THEN '苹果'
    ELSE '其他'
END
```

**不要写 `ELSE '苹果'`**——`WindowsEditor`/`OSXPlayer` 这类内部测试机会被静默算进 iOS。

### 重复注册

`t_register` 里有账号存在两条记录（8/25 时点：iPhone 512 行对 511 人）。**取 os/country 必须先 `max(...) GROUP BY user_id` 聚合成一行再 JOIN**，否则人数放大。

## 二、时区（最容易出错的地方）

数数是**三层结构**：上报层带偏移属性 → 存储层归一 → **展示层按项目时区渲染**。切换右上角选择器只改展示层，底层时刻不变。

- **项目展示时区默认 UTC-4（西四）**，看板底层也是西四
- 8 月美东 EDT = UTC-4，所以看板的一天就是美东玩家的自然一天
- **11 月 2 日之后美东转 UTC-5**，固定 -4 会偏一小时（这轮不影响）

**关键判断**：

| 口径 | 受时区影响吗 |
|---|---|
| **24 小时桶**（`date_diff` 算秒差） | **不受**，两个时刻的差是固定的 |
| **自然日**（`date()` 取日期比较） | **受**，日界在哪决定跨不跨天 |

现有 SQL 绝大多数用 24 小时桶，所以时区怎么切都不影响。只有 q4（大盘日报）和"注册日"这个分组标签按自然日切。

**从注册数分布反推**：8/24 只有 168 人、8/25 有 1319 人，而测试从北京 8/24 15:00 开始 → 8/24 只覆盖 9 小时 → **该会话是东八**。但截图里选择器显示 UTC-4。**每次开工前确认一次。**

## 四、口径决策（已定，别再改）

| 项 | 决定 |
|---|---|
| 留存/LTV 时间轴 | **24 小时桶**，`date_diff('second',...)/86400` |
| 留存命名 | **第 N 日 = D(N-1)**：次日=D1、三日=D2、七日=D6、14日=D13 |
| ⚠️ 混淆点 | 留存的"七日"是 D6，但 LTV7 是 D7，**两个 7 不是同一天** |
| 付费率分母 | 当日活跃（大盘）/ 新增人数（新增质量表） |
| ARPPU 分母 | 当日付费人数 |
| LTV 分母 | 注册人数 |
| 观测期未满 | 每个 Dn 只统计满 n+1 天的人；加了注册日维度后整行同进同出 |
| 金额精度 | **整数分累加，最后一次转 DECIMAL**；比率一律 `nullif` |
| 样本阈值 | 分子 ≥30 可用 / 10-29 仅看方向 / <10 样本不足 |
| 呈现 | 表头和维度值全中文，排序走隐藏的日期列 |

### 分组口径

- **iOS**：全量
- **安卓_AEO**：`os_raw = 'Android' AND ad_series LIKE '%AEO%'`
- 非 AEO 安卓落到"其他"，滤掉

⚠️ `LIKE '%AEO%'` 是临时写法，**跑通后换精确值**——如果有 `nonAEO` 这种命名会被误伤，结论完全反过来。

### 场景大类

```
爬塔       = 10005, 3, 10033, 10028
三日新手礼 = 10027
商店/商城  = 8(轮播), 9(常驻), 10001(商城)  ← 有时也含 1,2,4,7 阶梯类，按需
BP/通行证  = 10006, 10015, 10017, 10025
```

⚠️ **SCENE_TYPE 45 条里付费活动和活跃活动混在一起**，做付费分析不能整表当付费场景。分类需业务侧给，我不自行判断。

## 五、已得结论

### 确定的

1. **付费留存双端无差异**。次日 66.7% vs 65.9%，各节点差值都在 4pp 内且方向摆动。双端加权：66.3% / 55.1% / 39.8% / 33.3% / 27.0%
2. **付费留存没有下降趋势**。次日留存按注册日在 62-72% 波动，之前看到的"下降"是被未满期数据误导
3. **衰减断点在第 3→4 天**。iOS 阶段值逐段掉 33.3 / 12.7 / **14.6** / 5.3 / 5.3 pp，第 4 天后走平
4. **首笔→次笔转化 52.1% 是全链路最低点**。之后各档 60-93%，买过第二次的人基本会一直买
5. **收入极度集中**：13.5% 的人（买 5 笔以上）贡献 49.8% 收入；前 4 笔累计 73.4% 收入
6. **和上一轮比复购全面改善**：付费人数 87→512，首笔→次笔 46.0%→52.1%，人均笔数 2.5→3.06
7. **iOS 变现优势只在首日**。排除异常的 8/28 后，iOS/安卓 LTV0 约 1.1-1.3×；但次日/当日的增长倍数两端几乎相同（1.66 vs 1.65）
8. **安卓首日变现在改善**：LTV当日 从 8/25 的 $0.20 升到 8/29 的 $0.36

### 待验证的

- **8/28 iOS 是异常值**：LTV当日 $0.76，是自身其他日的 2 倍、安卓同日的 2.45 倍。763 用户下一笔大额订单就能造成，**需查有无大 R**
- **8/26 队列两端双低**：留存和 LTV 都是最差的一组。可能是投放来源问题
- **8/27 队列 3 日留存两端同步跌到 43%**，8/28 又回到 63%。平台无关的同步波动 → 投放或游戏侧事件
- **爬塔留存最差（24h 34.9%）但接了 54% 的破冰**。存在生存者偏差：爬塔是首日主推位、接最泛人群；商店组（53.8%）的人是主动找过来的。**这个差异有多少来自礼包本身、多少来自人群自选，现有数据分不出来**
- **上一轮体力转盘接了 25% 破冰，本轮只剩 0.5%**。爬塔占比从 37.9% 涨到 59.8%，很可能是接走了体力转盘让出的量。**需确认体力转盘这轮是否下线**

## 八、方法论备忘（每条都错过一次）

1. **必须有对照组**——"体力耗尽导致流失"加入 Core 组后立即证伪
2. **对随位置变化的群体不可做差分**——累计中位数做 diff 算出"产出为负"是伪影
3. **分箱要做宽度稳健性检验**
4. **看全部数据点**——"产出崩塌 8.4 倍"是只挑偶数位置造成的
5. **中位数 ÷ 中位数 ≠ 逐人比值的中位数**——金币倍数从 2027 修正到 561
6. **均值受极值主导时看中位**
7. **相关性显著 ≠ 因果**——付费面板与流失 p=0.0064，但 231 条全是曝光无人点击
8. **字段名 ≠ 业务含义**——`coin_cnt = 0` 解读成"什么都没得到"是臆测
9. **枚举先行**——上轮撤回 6 条结论，全因拿到数据时不知字段含义
10. **决定精度的是分子不是分母**——相对标准误 ≈ `1/√分子`。45 人的分段，留存分子 16 可看方向，付费分子 1.3 完全无意义
11. **"阶段值"这类跨队列汇总不能横向读**——每列参与的队列不同。iOS LTV 出现 3日 $0.63 → 4日 $0.09 就是这么来的，不是真实回落
12. **观测期未满会伪造下降曲线**——持续导量时，最新队列永远显示更差
