# PiggyTycoon 付费相关数据导出 SQL 说明

## 数据源结构（背景，交接时务必带上）
- `v_event_261`：所有埋点事件共用的一张宽表（不是一个事件一张表）。
  用 `"$part_event"` 字段区分事件类型（比如 `t_register` / `t_pay_flow`），
  用 `"$part_date"` 字段做按天分区，查询时必须带上 `$part_date` 过滤条件，
  否则会全表扫描导致巨慢或报错。
- `ta.v_user_261`：独立的用户属性表，存的是每个用户【当前最新】的属性
  快照（等级、金币、累计付费金额等），不是事件流水。

## 队列/人群定义（3份文件共用的筛选条件）
"测试用户"统一指：地区为 US 或 GB，且注册时间 ≥ 2026-07-21 00:00:00 的玩家。

---

## 文件① export_payflow_gb_us_0721_v2.sql
**用途**：导出这批测试用户的全部支付流水（t_pay_flow 事件的每一笔订单）。
**输出**：一行 = 一笔支付记录，包含 cost（金额）、cur_code（币种）、
order_id 等 pay_flow 字段，外加注册国家/注册时间两列方便核对。
**用来做什么**：核对/统计这批测试用户的实际消费明细，比如按天/按用户
汇总消费金额。

## 文件② paying_players_account_id_list_v2.sql
**用途**：从上面同一批测试用户里，找出【至少付费过一次】的 account_id
名单（去重后的账号ID清单，不含任何金额/属性字段）。
**输出**：一行 = 一个付费玩家的 account_id。
**用来做什么**：仅仅是一份"名单"，本身不直接用来分析，是文件③内部会
再用一次的中间结果——如果你只是想拿到"这批人里谁付费了"的清单去导入
到别的系统/分群工具，才需要单独跑这份；否则可以跳过，直接跑文件③。

## 文件③ export_paying_players_user_attributes_v2.sql
**用途**：在文件②的付费玩家名单基础上，去 `ta.v_user_261` 用户属性表
里拉出这些人的完整用户属性快照（等级、金币存量、累计付费金额等所有
字段）。
**输出**：一行 = 一个付费玩家的当前用户属性（多字段）。
**用来做什么**：分析付费玩家的画像/属性分布，或者跟文件①的消费流水
用 account_id 做二次匹配，看"什么样属性的用户消费更多"。

---

## 三者关系
```
文件① (支付流水明细)  ─┐
                       ├─ 都基于同一个"测试用户"定义(注册>=7.21, US/GB)
文件③ (付费玩家属性)  ─┘     文件③ 内部已经包含了文件②的逻辑
                              (文件②是可选的独立中间产物，非必需)
```

## 交接时需要提醒对方确认的地方
1. `v_event_261` / `v_user_261` 的账号主键字段名是否都叫 `"#account_id"`
   （目前假设一致，未逐一验证）。
2. `"$part_date"` 的存储格式是否为 `'YYYY-MM-DD'` 字符串，如果格式不同
   需要调整比较写法。
3. "付费玩家"目前是【历史全量累计】口径（只要在 t_pay_flow 里出现过
   就算），不区分是否在测试窗口内付费。
