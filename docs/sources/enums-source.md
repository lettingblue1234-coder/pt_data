## PAGE_TYPE 页面

共 110 条（完整清单需重新上传 `PAGE_TYPE.csv`）。

⚠️ **`page_id` 是场景内局部编号，跨场景重号**。查询必须 `(scene_id, page_id, user_action)` 三个一起限定，单独用 `page_id` 会串。

常用段：

| 段 | page_id | 内容 |
|---|---|---|
| 礼包·外层 | 26 / 27 / 28 | 入口 / 主界面 / 关闭 |
| **礼包·成交链** | **29–34** | 二次确认框 / 确认 / 取消 / 一键购买 / 档位购买 / 未解锁提示 |
| **通行证·成交链** | **35–40** | 购买选择界面 / 高级说明气泡 / 普通购买 / 高级购买 / 禁用态 / 保险箱说明 |
| 通行证·外层 | 57 / 58 / 59 / 60 | 入口 / 界面 / 收集奖励 / 购买按钮 |
| 新手三日礼 | 65 / 66 | 支付按钮 / 领取按钮 |
| 商城 | 1 / 2 / 41 / 42 | 入口点击 / 免费奖励 / Banner / **购买按钮-首充状态** |
| 付费爬塔 | 24 / 25 | 点击未解锁 / 点击已解锁 |

29–34 和 35–40 这两段是基建文档里没列出来的。**做礼包漏斗缺了它们，等于跳过「点了购买」到「确认下单」的全部环节**——上一轮 `t_pay_step` 显示 419 人进付费流程只有 18 人成交，断点很可能就在这里。

有 **22 条标着「0.6.0 弃用」**，含 72/73/74（三段礼包旧入口，已被 26/27/28 取代）。**若本轮这些 ID 仍有数据，说明客户端版本或埋点没跟上**——是个现成的版本校验点。

## 行为字段

`t_user_track` 的两个关键枚举。**上一轮把这两个搞反，撤回了 6 条结论。**

| 字段 | 值 | 含义 |
|---|---|---|
| `user_action` | **2** | **曝光**（多为弹窗） |
| | **1** | **点击**（玩家主动） |
| | 0 | 默认 |
| `trigger_time` | 101 | 玩家主动点击 |
| | 0 | 自动曝光弹出 |

入口一般是曝光，点击必须玩家触发；界面既可能弹窗也可能主动点开，**同一个 page_id 的 1 和 2 要分开统计**，不要合并。

曝光只覆盖部分收入（上一轮 `t_user_track` 只对上 52.6% 的付费收入），**不要用曝光侧人数当付费漏斗的分母**。
