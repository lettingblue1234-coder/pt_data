# PT 配置设计工作流

项目：**Piggy Tycoon**（PT，project_id 261）。目标：新增/修改配置前，先把"现状 + 排期 + 代码约束 + 数据基线"摸清，再出方案；不凭记忆猜配置。

## 信息源地图

| 要什么 | 去哪拿 | 备注 |
|---|---|---|
| 项目总览、当前版本、文档入口 | 飞书【首页】 | **每次配置开始前先浏览**，再决定读哪些子文档 |
| 排期、版本节奏、功能上线时间 | 飞书知识库 | 涉及排期的任何结论都要引用知识库，不要口头推断 |
| 线上配置（测试服 / 体验服 / 预发布服） | **pango-MCP** | 三套环境都能读；对比时标明环境，别混 |
| SVN 上的配置/资源 | **pango-MCP**（SVN 能力） | 看改动历史、未发布的配置版本 |
| 客户端逻辑 | **本地已拉取的客户端代码** | 查 UI 入口、触发条件、配置字段如何被读取 |
| 服务端逻辑（发奖、触发、限购、重置） | 飞书里问 **PT开发小助手** | 服务端代码不在本地；把问题问具体并记录答复 |
| 数据基线（付费率、转化、留存等） | **AE（数数）MCP**；无 MCP 时用 `ae-cli`（见 `ae-cli-auth`） | SQL 口径见 `pt-ae-sql` / `piggytycoon-sql` |

## 标准流程

1. **自检工具**：pango-MCP、飞书、AE-MCP 是否可用。不可用就明说缺哪个、哪些结论因此是"未验证"，不要拿旧文档冒充线上现状。
2. **飞书【首页】**：浏览，记下和本次配置相关的页面（需求、数值、埋点、排期）。
3. **排期**：到知识库确认本需求目标版本、前后依赖功能（例如是否与新手引导、三日新手礼、爬塔同期上线）。
4. **读线上配置（pango）**：先读**同类已有配置**当模板，再看目标环境是否已有半成品。三套环境对照读，并读 SVN 最新版，标出差异。
5. **查代码**：客户端查触发/展示/读表；服务端不确定的点（发奖时机、重复购买、过期、与其他礼包互斥/优先级）问 PT开发小助手。
6. **取数**：用 AE 拉基线（口径沿用 `pt-ae-sql`，注意 D1 命名差异）。
7. **出方案**：配置草案 + 取舍理由 + 待确认项 + 验证/监控口径。**写配置前**让产品确认关键参数。
8. **回写**：确认下来的配置事实、踩坑、口径，更新到本 skill 或 `references/`。

## 通用约束与口径（已在仓库内确认）

- **按 ID 聚合，不按中文名**：`trade_id` 中文名不唯一（如 6005001~6005006 都叫「三段礼包」）。
- 商品权威来源：`Pay.xlsx` 的 `ProductList`；价格 ID 即价格（美分）。见 `piggytycoon-sql/references/enums.md`。
- 场景 `scene_id=1` = 阶梯_三段式礼包；`10027` = 三日新手礼活动。
- 礼包页面埋点：外层 26/27/28，成交链 29–34；72/73/74 为旧三段礼包入口（0.6.0 弃用）。
- 「首日」：**D1 = 注册当天**（`pt-ae-sql`，`life_day = date_diff + 1`）；留存口径 D1=次日，勿混。
- 项目已知基线（2026-09-01 快照，引用前核对时点）：收入约 72% 集中在首日；首笔→次笔转化 52.1% 为付费链路最低点；卡点在阶段 4。见 `piggytycoon-sql/references/project-context.md`。
