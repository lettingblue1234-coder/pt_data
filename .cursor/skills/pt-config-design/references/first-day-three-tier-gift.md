需求：在玩家**第一天**（注册当天，`life_day=1`）加一个**三段式礼包**。

## 第 1 步：读（不要先设计）

1. 飞书【首页】→ 找礼包/付费/新手期相关页面。
2. 知识库 → 本需求目标版本与排期；同期是否有改动首日流程的功能。
3. pango（测试服、体验服、预发布服各读一遍 + SVN）：
   - 现有 `scene_id=1` 三段礼包的配置：段数、每段奖励、价格 ID、解锁/触发条件、展示时机、有效期、限购。
   - `ProductList` 里 6005xxx 各档是否已被其他入口占用；首日礼包是**复用**还是**新增**商品 ID。
   - 三日新手礼（10027）配置：避免首日弹窗/奖励/价格带冲突。
   - 与新手引导的先后关系（首日何时允许弹付费）。
4. 客户端代码：礼包入口与弹出条件、读表字段、埋点（`scene_id`、`page`、`trade_id`、`packagekey` 是否已落地）。
5. PT开发小助手（服务端）要问清：
   - 是否支持「首日」条件（注册时间窗/玩家生命日）作为触发？
   - 三段之间的状态机：购买一段后下一段何时解锁、过期怎么算、断档怎么处理？
   - 发奖幂等、重复购买、与其他礼包互斥/优先级？
   - 新增商品 ID / 新增 scene 是否需要服务端改动或发版？

## 第 2 步：要拉的数据（AE）

口径沿用 `pt-ae-sql`：事件表 `hive.ta.v_event_261`（必带 `"$part_date"`），用户表 `hive.ta.v_user_261`，`pay_amt` 为美分。

| 问题 | 指标 |
|---|---|
| 首日可付费人群有多大 | 首日活跃数、首日到达关键进度（如阶段 4/5）的比例 |
| 首日现有付费形态 | 首日付费率、首日各 `trade_id` / `scene_id` 付费人数与金额分布 |
| 价格带 | 首日首笔金额分布（美分档），首笔→次笔转化（基线 52.1%） |
| 现有三段礼包表现 | `scene_id=1` 曝光→点击→成交（page 26–34 漏斗；注意 `user_action` 1=点击、2=曝光） |
| 与三日新手礼的重叠 | 10027 首日曝光/成交；买了 10027 的人是否也会命中新礼包 |
| 次日影响 | 首日付费 vs 未付费的次日留存（留存口径 D1=次日，注意区分） |

观测期必须写死截止时刻；未满期的数据不要拿来比较趋势。

## 设计时的判断提示（需用数据校准，不是定论）

- 首日收入集中度高，首笔→次笔转化是最弱环节：三段式的价值假设应落在"提高首笔后的第二笔转化"，方案里要明确第 1 段价格带是否贴近现有首笔价格。
- 卡点在阶段 4、付费多在阶段 5 之后：首日礼包触发点要放在**玩家已到卡点附近**，还是更早做破冰，需用到达率数据决定。
- 价格带优先复用 ProductList 已有档位（99–599），新增商品 ID 通常要联动支付商品配置与服务端。
