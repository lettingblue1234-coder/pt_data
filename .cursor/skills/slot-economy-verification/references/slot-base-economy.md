## 2. 单次spin结果层（对应`SlotBase`概念/早期"图1"）

单次spin在同一个`SlotGroupID`（机台基础概率组，如1001）下，有12类互斥宏观结果，
权重总和=100000：

| 结果 | 说明 |
|---|---|
| 1/2/3金币 | 卷轴上出现1/2/3个C图标（且其余位置不是能构成其他中奖组合的图标） |
| 1/2/3主题 | 同理，D图标 |
| 盾/炮/偷/体力/777 | 三个图标完全一致(S/S/S、A/A/A、R/R/R、E/E/E、L/L/L) |
| 空 | 三图标组合无法构成以上任何一种（杂色组合） |

**金币RTP基准定义**：机台自身"金币总期望" = Σ(每类结果概率 × 该结果金币产出)，
这是**100%基准线**，不算在"RTP"这个词里，是既定底层产出。运营活动的"金币RTP"
是在这条基准线之上的**额外返还比例**（详见第6节）。

## 3. 图标组合层（`SlotWeight`，对应早期"图2"）

`SlotWeight` 定义卷轴三个位置具体落什么图标组合，每行=一个具体组合+权重。
25行组合按"含几个C/含几个D/三连/杂色"分别求和，正好精确对应第2节的12类宏观结果
（已用真实配置表核对过，完全吻合）。

- 字段 `Interval`（间隔）：只有三连大奖行（盾/炮/偷/体力/777）非0（5/5/5/10/0），
  推断是"该结果触发后，间隔多少次spin内不会再次触发"（防连续爆奖的pity机制），
  **未经产品正面确认**。

## 4. 图标→奖励映射（`SlotIconType` → `SlotEvent`）

`SlotIconType` 把图标(单字母code)映射到`ResultType`（如"小金币"/"中金币"/"大金币"），
`SlotEvent` 再把`ResultType`映射到具体奖励(`ItemID`+数量)：

| ResultType | ItemID | 数量(举例) |
|---|---|---|
| 小/中/大金币 | 1002 | 500/1000/5000 |
| 小/中/大主题 | (主题对应ItemID) | 100/200/1000 |
| 777 | (777对应ItemID) | 10000 |
| 体力 | 2001 | 5 |
| 盾 | (盾对应ItemID) | 1 |
| 炮/偷 | 无固定值 | 由独立小游戏逻辑决定（攻击/偷取对象、金额），不走这张表 |
| 挖宝小/中/大积分 | BaseScore=1/1/1 | 分数直接累加，不换算 |
| 组队蛋糕小/中/大体力 | BaseScore=1/3/6 | 同上 |

> 注意：`PointsRaceStage`奖励表里出现的 ItemID=1001（大额金币类奖励）与这里的
> ItemID=1002 是否是同一件东西，尚未核实，可能是不同的物品ID体系，见open-assumptions。

## 5. 运营事件替换机制（`SlotReplaceWeight` + `SlotReplaceGroup`）

当特殊活动开启（积分事件/组队蛋糕/挖宝/高Bet宝箱），原生结果会按**级联互斥分支**被替换：

```
原始结果触发(如"小金币"，原生概率11%)
  → 判定是否落入替换事件1（如→1积分，12%）
    → 若否，判定是否落入替换事件2（如→2积分，5%）
      → 若否，维持原始结果（如小金币，剩余83%）
```

替换1+替换2+...+维持原样 = 100%，**不是独立叠加，是级联分支**。

`SlotReplaceWeight` 按 `ResultType`（小金币/中金币/小主题/中主题/无）分别定义这条替换链，
每一级替换目标是一个 `SlotReplaceGroupID`（如2001/2002/2003），
`SlotReplaceGroup` 再定义该ReplaceGroupID具体的图标组合(P/K/H/B等)+组内权重，
结构与`SlotWeight`平行。

**动态调控公式**（用于"金币水池"/积分事件放水-压制）：
```
放水/加成状态：最终替换概率 = AmpCoef × (加成系数+1) × 原始万分位概率
压制状态：      最终替换概率 = (1 - DecayCoef × 压制系数) × 原始万分位概率
```
其中"加成系数/压制系数"由积分事件的`PointsRaceNodeBUpdate`表算出（见另一份参考文档）。
`AmpCoef`/`DecayCoef` 若为0，代表该替换事件不受水池调控影响（如目前的组队蛋糕、Bet宝箱、
以及**双/三积分图标**——最后这个是已知待补漏洞，见SKILL.md"已知设计缺口"）。

## 6. 运营活动RTP规划（早期"图4"）

以"消耗100体力"为统一基准衡量活动价值：

- **体力RTP**：活动把消耗掉的体力"返"回来一部分，延长游戏时长/循环次数
- **金币RTP**：活动在机台基准线之上，额外折算给玩家的金币加成比例

多活动同时在线时：
```
总体力回收率 = Σ(各在线活动体力RTP)
总金币回报率 = 100%(机台基准) + Σ(各在线活动金币RTP)
```

已知活动清单（部分，具体数值见原规划表）：积分事件(体力RTP 50%/金币RTP 20%，常驻)、
机台升级活动(5%/2%，常驻)、每日任务(2%/2%，常驻)、锦标赛(5%/2%，限时)、
7日登录(3%/2%，限时)、高bet活动(0%/0%，限时)、组队活动(6%/2%，限时)、
代币抽奖活动(6%/2%，限时)。爬塔活动数值待补。

## 7. Bet宝箱系统（`SlotBet`/`SlotBetBase`）

高bet解锁：卷轴增加B(宝箱)图标，按bet档位(1/2/3/5/10/...10000)配置。
`OpenEnergyMin` 推断为"玩家在该bet档位下，累计消耗体力达到此门槛后宝箱图标才开始出现"。
`BetGroupID`=3001(普通)/3002(可能带增益buff)两组奖励参数不同(ItemID Param 30001-9 vs 30101-9)，
具体buff差异未确认。
