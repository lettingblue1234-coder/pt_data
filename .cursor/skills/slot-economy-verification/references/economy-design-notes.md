# SLOTS+ 经济设计要点（从膨胀分析提炼）

来源：`docs/sources/slots-economy-inflation-v4.md` + `slot-economy-summary.md`。用于产品/数值讨论；**线上公式验证**仍以本 skill 的 slot-base / points-race references + `scripts/checkpoint_calc.py` 为准。

## 两套「购买力」不要混谈

| 阶段 | 玩家体感 | 设计意图 |
|---|---|---|
| **开局钩子（短）** | 同额美元能买到更多体力（如 400→600→800） | 获客爽感，越短越猛越好 |
| **长期温和膨胀** | 钱越来越「不经花」、推进变慢 | 维持「现在花比将来划算」，驱动商业化 |

开局购买力上升 ≠ 长期通胀失控；前者是烟花，后者才是发动机。

## 为什么必须温和膨胀

- 若体力供应涨得比消耗快 → 玩家「等就有、不必花」→ 通缩螺旋，商业化死亡
- 目标不是零通胀，而是**可预期的温和缺口**（类比央行 ~2% 目标）

## 膨胀的两条承载曲线

1. **流水/难度目标**：推进越深门槛跳涨（分档上台阶，非匀速）
2. **兑换效率**：体力→金币、美元→体力的汇率分档跳涨

两条涨幅设计为持续超过体力供应涨幅；**缺口 = 引擎**。跳档瞬间可能短暂出现「购买力回涨窗口」，与开局钩子不是一回事。

## 费雪映射（Slots）

```
M（体力供应）× V（流通速度）= P（金币消耗物价）× Q（真实内容产出）
V ≈ 1 / (1 - RTP)   # 机台返比相关
```

机台基准「金币 RTP」在本项目里更准确说是：**耗 1 体力 → 基准产出 X 金币（100% 线）**；活动「金币 RTP」是该基准之上的**额外**返还，可叠加。验证时见 `slot-base-economy.md`。

## 与卡点系统的衔接

长期体验还靠积分事件三段区（奖励关 / 过渡关压制 / 卡点关硬阀门）+ 付费水池独立通道调节「感觉值不值」。节点 a/b 用**第几个大节点**计数，不是 StageID。细节见 `points-race-checkpoint.md`。
